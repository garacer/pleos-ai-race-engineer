# 플레오스 AI 레이스 엔지니어

**한 줄 소개:** 서킷 주행이 끝나면 레이스 엔지니어가 무전으로 말하듯, 내 주행 기록을 짧은 메시지 다섯 장과 한국어 음성으로 정리해 주는 Pleos 차량용 앱입니다.

- 팀명: 플레오스 AI 레이스 엔지니어
- 버전: 0.4.1 (versionCode 12)
- 패키지: `com.jev.drivecoach.dashboard`
- 언어/플랫폼: Kotlin, Android API 28 이상, Pleos Connect (AAOS, API 34)

> 현재 범위는 **정차 후 복기(디브리프)**입니다. 실차 실시간 안내, 실제 브레이크 신호 기반 제동점, 검증된 최적 라인, 노면 AR은 제공하지 않습니다.

## APK 위치

- 서명된 release APK: [`apk/플레오스AI레이스엔지니어_플레오스AI레이스엔지니어_release.apk`](apk/)
- 이 APK는 팀이 관리하는 release 키로 서명되어 있고, 디버깅이 꺼진 빌드입니다.

## 실행 방법

### 1) APK 설치 (가장 빠른 방법)

Pleos 에뮬레이터를 실행한 뒤:

```sh
adb install "apk/플레오스AI레이스엔지니어_플레오스AI레이스엔지니어_release.apk"
adb shell am start -n com.jev.drivecoach.dashboard/com.jev.drivecoach.DashboardActivity
```

같은 패키지의 다른 서명 빌드(예: debug)가 이미 설치돼 있으면 `adb uninstall com.jev.drivecoach.dashboard` 후 설치합니다.
런처에서는 **플레오스 AI 레이스 엔지니어** 아이콘으로 실행할 수 있습니다.

### 2) 소스에서 빌드

```sh
./gradlew testDebugUnitTest assembleDebug
./gradlew lintRelease assembleRelease
```

Windows에서는 `gradlew.bat`를 사용합니다. 의존성이 캐시에 있으면 `--offline`을 쓸 수 있습니다.

- debug 출력: `app/build/outputs/apk/debug/app-debug.apk`
- release 출력: 서명 설정 파일이 있으면 `app-release.apk`, 없으면 `app-release-unsigned.apk`

release 서명 정보는 저장소에 넣지 않습니다. 빌드할 때 저장소 밖의 properties 파일을 읽습니다.
(`-PjevSigningProps=<파일>` 또는 환경변수 `JEV_SIGNING_PROPS`, 기본값 `~/.config/jev-signing/keystore.properties`)

## 테스트 환경 및 필요한 설정

| 항목 | 값 |
|---|---|
| JDK | 17 |
| Gradle / AGP / Kotlin | 8.9 (wrapper) / 8.7.3 / 2.0.21 |
| SDK | compileSdk 35, targetSdk 34, minSdk 28 |
| Pleos SDK | Vehicle 2.3.2, TextToSpeech 3.3.1 (`settings.gradle.kts`의 공식 Pleos Maven 저장소) |
| 에뮬레이터 이미지 | `system-images;android-34;pleos_car_emulator;x86_64` (Pleos Connect 2.1.0 / Android 14) |
| 검증 화면 | 2560×1440 (`-skin 2560x1440`), 2코어/2GB RAM, SwiftShader |

- 앱 화면은 **2560×1440**에서 검증했습니다. 기본 320×640 화면에서는 앱 영역이 매우 좁게 나옵니다.
- 인터넷 권한을 쓰지 않습니다. 모든 기록 데이터는 앱 안의 assets로 들어 있습니다.
- 요청 권한: `pleos.car.permission.CAR_DOORS`(문 상태 읽기 전용), `pleos.car.permission.TTS_SERVICE`(한국어 음성).

## 라디오 디브리프

대시보드에 숫자를 늘어놓지 않습니다. 한 장에 메시지 하나, 큰 글씨 하나, 그림 하나만 보여 주고 엔지니어 음성이 읽어 줍니다.

| 순서 | 화면에 크게 | 엔지니어 음성 | 그림 |
|---|---|---|---|
| 1. 오늘 세션 | **1:40.4** | "수고했어요. 오늘 베스트는 7랩, 1분 40초 4." | 랩 막대 (아웃·인 랩은 점선) |
| 2. 남은 시간 | **0.8초** | "섹터 베스트만 이으면 1분 39초 6. 아직 0.8초 남았어요." | 베스트 랩 대 이론상 베스트 |
| 3. 어디서 | **턴 2 → 턴 7** | "이 구간에서 4랩보다 0.5초 늦었어요." | 서킷에서 해당 구간만 빨간색 |
| 4. 잘한 점 | **코너 속도 5/5** | "다섯 곳 모두 4랩보다 빨랐어요. 이건 그대로 가져가요." | 코너마다 속도 차이 표시 |
| 5. 미션 | **섹터 2, 4랩처럼** | "섹터 2를 4랩처럼, 32.1초. 나머지는 지금처럼." | 서킷에서 섹터 2만 강조 |

- **▶ 엔지니어 브리핑 듣기:** 다섯 장을 차례로 읽으며 자동으로 넘어갑니다. ‹ › 버튼, 스와이프, 방향키로 직접 넘길 수도 있습니다.
- **주행 중:** 차량의 UX 제한이 걸리면 미션 한 줄만 크게 보여 주고 음성을 멈춥니다.

### 분석 규칙 (`PitBriefing.kt`, `Debrief.kt`, 단위시험)

- 중앙값의 110%보다 느린 랩은 플라잉 랩이 아닙니다. 첫 랩은 아웃 랩, 마지막 랩은 인 랩으로 분류하고 평균과 목표에서 뺍니다.
- 섹터 중앙값의 115%보다 느린 섹터는 베스트 계산에서 뺍니다. 이론상 베스트는 섹터 베스트의 합(1:39.6)입니다.
- 미션 목표는 플라잉 랩에서 나온 섹터 기록만 씁니다(인 랩 9랩의 S2 32.0초 대신 4랩의 32.1초).
- "어디서"는 4랩과 비교 가능한 연속 코너 사이에서 누적 시간차가 가장 크게 벌어진 구간입니다.

## 2분 시연 순서

1. 앱을 열면 첫 장 "오늘 세션 1:40.4"가 나옵니다.
2. `▶ 엔지니어 브리핑 듣기`를 누르면 다섯 장이 음성과 함께 자동으로 넘어갑니다(약 1분).
3. 마지막 미션 장에서 "다음 세션에는 이것 하나만"이라는 콘셉트를 설명합니다.
4. (선택) 주행 중 제한 상태에서는 미션 한 줄만 남는다는 점을 보여 줍니다.

## 화면 데이터의 의미

| 항목 | 근거 | 제한 |
|---|---|---|
| 랩·섹터 시간 | 사용자 주행 기록 9랩 | 현재 실차 기록 아님 |
| 서킷 경로 | 베스트 7랩 GPS 487개 지점 | 공식 측량 정합 미검증 |
| 코너 속도·시간차 | 7랩 대 4랩, 비교 가능한 코너 | GPS 추정 코너 위치(영암 10턴) |
| 음성 | Pleos TTS, 기기 안에서 합성 | 인터넷 사용 안 함 |

브레이크·TPMS처럼 실제 신호가 없는 값은 화면에 표시하지 않습니다.

## 검증 결과

- **0.4.1 서명 release (2026-11-12):** 앞 장의 음성이 아직 끝나지 않았을 때 다음 장 음성이 빠지던 문제를 고침(끝나는 즉시 이어서 읽음). 자동 재생이 끝날 때 마지막 장 음성을 끊지 않게 함. 페이지에 없던 `JEV_VEHICLE` 함수 오류 제거. 단위시험 61/61 통과, lint 오류 0 / 경고 12. Pleos 에뮬레이터에서 자동 재생 다섯 장, 음성 요청/시작/완료 5/5/5, 멈춤 버튼으로 발화 중 중지 확인, JS 오류 0. 에뮬레이터 오디오를 꺼 두어 물리적 청취는 확인하지 않았습니다.
- 0.4.0: 라디오 디브리프로 화면 전체를 새로 설계.
- 0.3.0: 버튼 목록 화면(MainActivity)과 1.6MB 대시보드, 더미 TPMS·브레이크, 과거 예시 MP3를 제거하고 랩 분석을 `PitBriefing`으로 분리. TTS 요청 시간 제한을 문장 길이에 맞게 늘림.
- 0.2.7: 앱 표시명을 "플레오스 AI 레이스 엔지니어"로 변경, release 서명 설정 추가.
- 0.2.6: 진단용 음성 버튼과 내부 진단 Activity를 debug 빌드에서만 사용하도록 제한.
- 0.2.5: 런처 아이콘, Android 12+ 데이터 추출 제외 규칙 추가(`allowBackup=false` 유지).
- **0.2.4 동적 한국어 코칭:** 깨끗한 Pleos AVD에서 ON_DEVICE 합성 요청/시작/완료 1/1/1과 엔진 출력을 확인했습니다. 물리적 청취는 독립 확인하지 않았습니다.

## 아직 하지 않은 것

물리적 음성 청취 확인, 다른 주행 기록 불러오기(현재 앱 안 기록 1세션), 7랩 외 랩의 GPS 경로, 실차 신호 연결, 실제 브레이크 입력, 노면 AR과 실차 실시간 안내.
